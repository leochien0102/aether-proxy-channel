## 实现

### channel

- `scripts/publish.sh` 落地 T11.14 补丁：URL 集合包含 packages current/previous、data、所有 compatibility steps。上传候选、上传后缺失检查、stale 删除均读取同一份 `$work/urls`。
- 可选 `COMPATIBILITY_FILE` 原样传给 builder 的 `--compatibility`；未设置时不增加参数，保持无链旧行为，并允许 builder 从旧签名 manifest 继承已有链。
- 显式设置（包括空字符串）时先读取并解析 JSON；缺文件/非法 JSON 在任何 `gh` 调用之前失败，不被 unchanged 分支静默跳过。
- builder 原有校验负责链顺序、required_steps、终点版本绑定、资产 hash/size、历史元数据一致性；失败不签名、不上传、不切换 manifest。
- `README.md` 说明输入格式、同目录历史资产、继承/清理规则和发布工具版本前提。

### app 测试（工作区修改）

- `tools/channel/test_build.py`：先用 `git apply --reverse --check` 判断临时脚本副本是否已有补丁；已部署时不重复 apply，旧脚本/冻结片段仍在临时目录打补丁。绝不改 `CHANNEL_ROOT` checkout。
- URL 枚举测试定位 `$work/urls` 对应 heredoc，避免新增输入预检 heredoc 后误取代码。
- `tests/release/test_rc_promotion.py`：fake gh 真正执行 delete-asset，并可模拟上传丢失文件；使用真实 publisher 和 builder、离线数据与假签名器。
- 新增六项 publisher 测试：
  1. 显式输入写入 manifest、上传历史 bridge 包；随后没有本地输入/bridge 字节的数据更新保留链和全部 bridge 字节，仅删除 stale。
  2. 无 compatibility 时保留 current/previous 与新 data，删除未引用包，manifest 不新增 compatibility。
  3. 缺文件、非法/空 JSON、空环境变量在 release 操作前失败。
  4. null/空对象/无效链、坏 hash、缺 bridge 源文件阻断上传。
  5. 模拟 bridge 上传后缺失，存在性检查阻断 manifest 切换与清理。
  6. 已发布 bridge 引用仍在但远端文件丢失，阻断 manifest 切换与清理。

## workflow 决策与边界

未修改 `promote.yml`：现有 RC 契约只有 20 个包及两份元数据，没有可信 compatibility 文件来源；本次不伪造/自动生成链，不增加一个无人提供文件的输入。

维护者可以通过脚本环境变量显式提供审核过的文件和资产；builder 将 compatibility 与 current 版本及资产 hash/size 绑定进最终签名 manifest。未来若接入 workflow，必须明确来源，并让预检与最终发布使用同一份输入。

`AETHER_PROXY_REF` 未改；当前固定的旧 ref 不会因本次脚本改动自动具备 T11.14 builder。使用新输入必须选择含 T11.14 的工具；旧 builder 不认识新参数时应失败，不能忽略。本任务仅部署 channel 脚本能力，不选择发布版本或实际发链。
