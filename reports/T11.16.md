# T11.16 完成报告（channel）

promote 链路接入 bridge compatibility：从 app RC prerelease 取受审文件，按其中的
url 从 RC 产物或既有 stable 下载历史 bridge 包并校验 sha256/size，缺任一资产立即
失败，把 `COMPATIBILITY_FILE` 与字节交给既有 `scripts/publish.sh`。不升版、不 push、
不打 tag、不实际发布。

## 改动

- `.github/workflows/promote.yml`：
  - 「Download and validate immutable prerelease」：rc-manifest 带 `compatibility`
    绑定时，预期 prerelease 资产集 22→23 并校验绑定名；全部 RC 校验（矩阵、版本、
    tag commit、两层 hash）通过后读取 compatibility 文件，对每步每资产校验元数据
    并解析字节——目标步必须就是本 RC 构建的 noarch aether-proxy 产物（按通道规则
    取 aarch64_generic 字节），历史步从既有 `channel-stable` 按名下载，两者皆无则
    明确报错立即失败（先于 preflight/签名/任何 release 操作）；下载后逐一校验
    sha256/size；每步必须 ipk+apk 齐备（缺格式会让该格式设备全体
    BRIDGE_UNAVAILABLE）。通过后写 `bridge/`（compatibility.json + 字节）并经
    `GITHUB_ENV` 导出 `COMPATIBILITY_FILE`。
  - 「Reject existing assets with different bytes」：preflight 加
    `--compatibility "$COMPATIBILITY_FILE"`，与最终发布同一份输入。
  - 不 checkout app 源码、不执行 SDK/make/编译（app 侧 contract 测试继续断言）。
- `README.md`：新增「Bridge 发布链路（T11.16）」一节；修正 T11.15 一节中
  「promote 没有 compatibility 来源」的过时表述。
- `scripts/publish.sh` **无改动**：T11.15 已实现 URL 集合/资产清理保留、
  `COMPATIBILITY_FILE` 缺文件/非法 JSON 在任何 release 操作前失败、无链行为不变。
- `AETHER_PROXY_REF`、版本、keys 未动。

## 偏差与待定

- `promote.yml` 新增 `GITHUB_ENV` 依赖用于步骤间传递 `COMPATIBILITY_FILE`；
  app 侧测试 harness 以 Actions 相同语义回放。
- app 仓提交的 compatibility 链（0.6.2-1→0.6.3-1）是待补齐草稿（无 apk 资产），
  promote 的 ipk+apk 检查会拒绝它——这是有意失败关闭，详见 app 仓报告。
- 发现既有隐患（未改）：promote/RC 期望 ipk 版本名为 `-r<N>`，真实发布产物为
  `-<N>`（仅 luci-app 为 `-r1`）；首次真实 RC 可能失败，打 tag 前需核实。
