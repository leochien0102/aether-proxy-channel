# T11.12 — channel RC 晋升（不升版）

## 实现

分支：`t11.12/rc-promotion`。

新增 `.github/workflows/promote.yml`：只允许 main 的 workflow_dispatch，输入 app `rc_tag`。

1. 下载公开 app prerelease 的 20 包和两份清单，校验完整矩阵、版本、架构、文件名、RC tag/commit/目标正式 tag，以及 SHA256SUMS 和 rc-manifest.json 两层 hash。
2. 仅从 RC commit 获取两份独立 publication Python 工具和四份 Makefile 版本元数据；不 checkout app、不调用 SDK、不运行编译器。usign 通过系统包安装。
3. 调用 `tools/channel/build.py --packages packages --out preflight`；若已有同名包不同字节或同版本不同资产清单则失败。与 packages/data 共用 `channel-publish` 并发锁。
4. 最后调用现有 `scripts/publish.sh publisher packages` 生成规则数据并签名发布 stable；`USIGN_SECRET_KEY` 只从最后一步的 Actions Secret 注入。

不改 `packages.yml`、`data.yml`、`scripts/publish.sh`、`scripts/usign.sh`、`AETHER_PROXY_REF`、keys 或版本。新增 README 说明。完整跨仓报告在 app 分支的 `reports/T11.12.md`。

覆盖 RC artifact→prerelease、promote 下载→真实 channel 生成器/publish→fake 签名与上传；坏 hash、缺包、非 prerelease、错误版本/commit、已有不同字节/不同清单均阻断；确认无 app checkout、无编译命令。fake signer 和离线规则数据不构成真实 usign、远端权限或 apt 安装实测。

## 边界

- noarch 仍按现有生成器选择排序最前的 `aarch64_generic` 路径，最终通常 14 个包文件；其字节均来自 20 个已校验 RC 包。
- 正式 tag 已存在时强制与 RC 同 commit；尚未存在时，后续必须由维护者在 RC commit 上创建并保护。按要求未改 app `release-assets.yml`，不能宣称自动约束未来错误 tag；它仍只按原门禁复制匹配的 channel 资产。
- 原 packages/data 路径保留；promote 不需要也不应再次触发 SDK 构建。已有同版本包字节不同会拒绝晋升，不覆盖、不静默冒充成功。
- 私钥未写入文件或仓库；没有版本 bump、真实 tag、push、远端 workflow 或实际发布。
